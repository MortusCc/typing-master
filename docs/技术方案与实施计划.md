## 1. 项目概述

### 1.1 目标

构建一个**纯前端打字学习网页**，部署在 GitHub Pages 上，帮助用户：

- 学习英文单词打字（结合中文释义与音标）
- 练习中文/英文文章盲打
- 屏幕常驻虚拟键盘，高亮待按键位，辅助养成盲打习惯
- 导入自定义训练素材（xlsx 单词表、TXT/Markdown 文章）
- 开箱即用：内置默认素材，无需导入即可开始
- 追踪打字速度（WPM）和正确率

### 1.2 核心原则

| 原则 | 说明 |
|------|------|
| **零后端** | 纯静态网页，所有数据本地存储，无需服务器 |
| **在线部署** | 部署到 GitHub Pages，用户通过网址直接访问 |
| **数据持久化** | IndexedDB 本地存储，同一浏览器数据跨会话保留，无需重新导入 |
| **素材可扩展** | 用户可导入任意 xlsx 单词表、TXT/Markdown 文章 |
| **开箱即用** | 内置默认素材（单词表 + 文章），无需导入即可开始练习 |
| **即时反馈** | 实时高亮当前字符，正确/错误颜色区分 |
| **盲打辅助** | 屏幕虚拟键盘实时高亮待按键位，培养不看键盘的习惯 |
| **隐私优先** | 所有数据存于浏览器本地，不上传任何服务器 |

### 1.3 用户故事

- 🧒 **小学生**：打开网页就能练，内置单词表 + 虚拟键盘指引指法
- 🧑‍💻 **打字新手**：从单词模式起步，看着虚拟键盘逐步过渡到盲打
- 📝 **文字工作者**：导入自己的文章素材，练习盲打
- 👨‍🏫 **老师/家长**：为孩子准备定制化打字素材

## 2. 现有素材分析

### 2.1 `小学英语单词音标表.xlsx` 结构

| Sheet | 行数 | 列数 |
|-------|------|------|
| 单词音标表 | 120 | 8 |

**列结构**：

| 列 | 字段 | 示例 | 用途 |
|----|------|------|------|
| A | 序号 | 1, 2, 3… | 排序依据 |
| B | 单词/短语 | `doctor`, `police officer` | **打字目标** |
| C | 英式音标 | `/ˈdɒktə(r)/` | 辅助展示 |
| D | 美式音标 | `/ˈdɑːktər/` | 辅助展示 |
| E | 中文 | `医生，大夫` | **提示/翻译** |
| F | 背诵时间 | `7.4 上午9:00…` | 可忽略 |
| G-H | （空） | — | — |

**格式特点**：
- 以 `Unit 1`, `Unit 2` 等行作为分组标记
- 标题行（Row 1）和表头行（Row 2）需跳过
- 某些行可能是分组标题（`None` 值），需过滤

### 2.2 支持的素材类型

| 类型 | 格式 | 字段要求 |
|------|------|----------|
| 单词表 | `.xlsx` | 至少包含"英文"和"中文"两列，可选音标列 |
| 英文文章 | `.txt` / `.md` | 纯文本英文内容，可选中文翻译段落 |
| 中文文章 | `.txt` / `.md` | 纯文本中文内容 |

## 3. 技术栈选型

### 3.1 推荐方案：React + TypeScript + Vite

| 层级 | 技术 | 选型理由 |
|------|------|----------|
| **框架** | React 19+ | 生态成熟，组件化开发，状态管理灵活 |
| **语言** | TypeScript | 类型安全，减少运行时错误，提升开发体验 |
| **构建** | Vite 6 | 极速 HMR，零配置起步，生产构建优化好 |
| **样式** | TailwindCSS 4 | 原子化 CSS，响应式方便，暗色模式内置 |
| **状态管理** | Zustand | 轻量（<1KB），API 简洁，无需 Provider 包裹 |
| **路由** | React Router v7 | SPA 路由标准方案 |
| **Excel 解析** | SheetJS (xlsx) | 纯前端解析 xlsx，支持所有 Excel 格式 |
| **本地存储** | Dexie.js + IndexedDB | 结构化大数据存储，比 localStorage 更适合素材库 |
| **虚拟键盘** | 纯 CSS Grid + React 组件 | 不引入额外依赖，高频率更新可控 |
| **图表** | Recharts | 轻量 React 图表库，适合 WPM 趋势图 |
| **部署** | GitHub Pages + Actions | 免费、稳定、自动部署 |
| **测试** | Vitest + React Testing Library | 与 Vite 同生态，配置简单 |
| **代码质量** | ESLint + Prettier | 统一代码风格 |

### 3.2 替代方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| **Vue 3 + Nuxt** | 上手快，中文社区好 | 生态插件不如 React 丰富 |
| **Svelte** | 打包体积极小 | 社区较小，复杂场景参考少 |
| **纯 HTML/JS** | 无依赖 | 功能复杂后难以维护 |
| **Next.js** | SSR 能力强 | 本项目不需要 SSR，增加复杂度；GitHub Pages 部署需额外配置 |

> **结论**：React + Vite + TypeScript 是最均衡的选择，既有足够生态支持复杂打字交互（实时高亮、虚拟键盘），又保持了纯前端的简洁性和 GitHub Pages 部署的便利性。

### 3.3 不选后端的原因

打字练习是**纯客户端计算**：计时、字符比对、虚拟键盘高亮、统计全部在前端完成。素材导入只需 SheetJS 在前端读文件，存储用 IndexedDB。不需要任何服务端功能。GitHub Pages 直接托管静态文件即可。

## 4. 功能模块

### 4.1 模块总览

```
打字学习网页
├── 🏠 首页 / 仪表盘
├── 🔤 单词打字模式（基础学习）
│   └── ⌨️ 虚拟键盘（常驻底部）
├── 📄 文章打字模式
│   └── ⌨️ 虚拟键盘（常驻底部）
├── 📦 素材管理
│   ├── 导入 xlsx 单词表
│   ├── 导入 TXT/MD 文章
│   ├── 素材列表管理
│   └── 内置默认素材（开箱即用）
├── 📊 统计与历史
└── ⚙️ 设置
```

### 4.2 模块详细设计

#### 4.2.1 首页 / 仪表盘

- 展示今日练习概况（时间、WPM、正确率）
- 最近练习的素材快捷入口
- WPM 趋势小图
- "开始练习"主按钮

#### 4.2.2 单词打字模式

**流程**：
1. 用户选择单词素材（如"四年级英语下"）
2. 系统从素材中随机/顺序抽取单词
3. 屏幕展示：
   - 中文释义（大字，作为提示）
   - 音标（小字，可选显示）
   - 输入区（用户打字位置）
   - **虚拟键盘**（底部常驻，当前应按键位高亮）
4. 用户输入英文单词，按空格/回车提交
5. 即时判定正确/错误，给出反馈（颜色+动画+键盘按键反馈）
6. 统计本轮：正确率、速度、用时

**虚拟键盘集成**：
- 页面底部常驻 QWERTY 虚拟键盘
- 当前应按键位高亮（蓝色边框 + 脉冲动画）
- 用户按下后短暂反馈：绿色闪烁（正确）/ 红色闪烁（错误）
- 手指分区颜色标注（左手区暖色底、右手区冷色底），辅助建立指法意识

**交互细节**：
- 正确：绿色闪烁 + 自动跳到下一个
- 错误：红色标记错误字符位置 + 显示正确答案 + 虚拟键盘错误键位红闪 + 该词加入"错题本"（稍后重练）
- 支持跳过（不会的词可以先跳过）
- 一轮结束后展示成绩单

**模式变体**：

| 模式 | 说明 |
|------|------|
| 顺序模式 | 按素材原有顺序出题 |
| 随机模式 | 随机打乱出题 |
| 错题重练 | 只练习之前错误的单词 |
| 限时挑战 | N 分钟内尽可能多打对 |

#### 4.2.3 文章打字模式

**流程**：
1. 用户选择文章素材
2. 屏幕上方展示原文（含翻译对照区）
3. 用户在输入区逐字输入
4. 实时高亮当前应打字符位置
5. 正确字符显示为已通过样式，错误字符红色标记
6. **虚拟键盘**同步高亮下一个应按键位
7. 打完文章后展示成绩单

**交互细节**：
- 原文区：每行文字，当前字符有光标指示
- 已输入正确的字符：灰/绿色
- 输入错误的字符：红色 + 下划线
- 未输入的字符：默认颜色
- 支持退格修改（但会影响 WPM 统计）
- 实时显示：WPM、正确率、进度百分比

**虚拟键盘集成**：
- 与单词模式共用同一虚拟键盘组件
- 文章模式中需按下标点符号（如 `. , ! ?`），虚拟键盘同样高亮
- 中文文章模式下，虚拟键盘仅作参考展示（中文输入法组合态期间不逐键高亮，仅显示手指分区色）
- 大文本时虚拟键盘更新频率为每按键一次，性能可控

**英文文章翻译对照**：
- 每段英文下方可折叠显示对应中文翻译
- 翻译在文章素材中以特殊标记分隔（如 `---translation---`）

#### 4.2.4 素材管理

**导入流程**：
```
选择文件 → 自动识别类型 → 预览解析结果 → 字段映射确认 → 保存到本地
```

**xlsx 导入向导**：
1. 上传文件
2. SheetJS 自动解析，展示前 5 行预览
3. 下拉选择：哪列是"英文/打字内容"？哪列是"中文/翻译"？哪列是"音标"（可选）？
4. 输入素材名称（默认取文件名）
5. 选择分类标签（单词/文章）
6. 确认导入

**文章导入**：
1. 上传 .txt 或 .md 文件
2. 自动检测语言（中/英）
3. 预览内容
4. 如果是英文文章，可选择上传对应的中文翻译文件
5. 确认导入

**素材管理界面**：
- 卡片列表展示所有素材（含默认素材，带"内置"标记）
- 显示：名称、类型、词条数/字数、来源（内置/用户导入）、导入日期
- 操作：练习、编辑名称、删除
- 搜索/筛选

#### 4.2.5 统计与历史

- **每次练习记录**：
  - 素材名称、模式（单词/文章）
  - 用时、WPM、正确率、总字符数、错误字符数
  - 日期时间
- **趋势图表**：
  - WPM 折线图（按日期）
  - 正确率折线图
- **概览统计**：
  - 总练习次数、总时长、平均 WPM、平均正确率
  - 最常错的单词 Top 10

#### 4.2.6 设置

- 暗色/亮色主题切换
- 字体大小调节
- 音标显示开关
- 虚拟键盘显示开关（熟练后可隐藏）
- 手指分区颜色开关
- 键盘音效开关
- 数据导出/导入（备份还原，跨设备迁移）
- 重置默认素材（删除后恢复内置素材）
- 清除所有数据

#### 4.2.7 虚拟键盘组件（核心新增）

**设计目标**：帮助用户养成盲打习惯——眼睛看屏幕上的虚拟键盘而非低头看实体键盘，建立手指-键位肌肉记忆。

**键盘布局**：
- 标准 ANSI QWERTY 布局（最通用的英文键盘布局）
- 5 行：数字行、上排、中排（Home Row）、下排、空格行
- 修饰键（Shift/Ctrl/Alt/Tab/Caps/Backspace/Enter）仅作视觉占位，不参与高亮
- Home Row 键位（`asdf` `jkl;`）有微弱的定位标记线

**键位状态与视觉**：

| 状态 | 视觉效果 | 触发条件 |
|------|----------|----------|
| 默认 | 灰底白字/黑字，轻微阴影 | 初始状态 |
| 待按下（next） | 蓝色边框 2px + 脉冲发光动画 + 缩放 1.05x | 打字引擎判定该键为下一个目标字符 |
| 正确按下（correct） | 绿色背景闪烁 200ms | 用户按下正确键位 |
| 错误按下（error） | 红色背景闪烁 200ms + translateX 震动 | 用户按下错误键位 |
| 左右手分区 | 左手区暖色调底（#fef3c7）、右手区冷色调底（#dbeafe） | 始终显示 |

**指法分区参考**（基于标准盲打指法）：

| 手指 | 负责键位 |
|------|----------|
| 左小指 | `` ` 1 q a z `` |
| 左无名指 | `2 w s x` |
| 左中指 | `3 e d c` |
| 左食指 | `4 5 r t f g v b` |
| 右食指 | `6 7 y u h j n m` |
| 右中指 | `8 i k ,` |
| 右无名指 | `9 o l .` |
| 右小指 | `0 - = p [ ] ; ' / \` |

技术实现上将此映射存储为常量，用于区分左右手分区底色。

**组件接口**：
```typescript
interface VirtualKeyboardProps {
  nextKey: string | null;            // 待按下的键位（来自 typingEngine）
  lastKeyResult: 'correct' | 'error' | null;  // 上次按键结果
  showFingerZones: boolean;          // 是否显示手指分区颜色
  disabled?: boolean;                // 禁用高亮（如中文输入法组合态期间）
}
```

**性能注意**：
- 虚拟键盘是高频更新组件（每次按键都要重渲染）
- 使用 `React.memo` + 仅传递变化的 props
- 键盘布局数据（`KEYBOARD_ROWS`, `FINGER_ZONES`）定义为模块级常量，避免每次渲染重建
- 动画使用 CSS transition/animation，不依赖 JS 动画循环
- 按下反馈使用 `keydown`/`keyup` 事件驱动，无轮询

**与 typingEngine 的协作**：
```
typingEngine.handleKey(key)
  → 返回 { result: 'correct' | 'error', nextChar: string }
  → typingStore 更新
  → VirtualKeyboard 接收 nextKey={nextChar}  lastKeyResult={result}
  → CSS 动画驱动高亮 + 反馈
```

### 4.3 内置默认素材

#### 4.3.1 设计理念

用户首次打开网页即可开始练习，无需先导入素材。默认素材作为静态资源打包在应用中，首次加载时自动写入 IndexedDB。

#### 4.3.2 默认素材清单

| 素材名称 | 类型 | 来源 | 内容概要 |
|----------|------|------|----------|
| 小学英语四年级下 | 单词表 | `public/default-materials/小学英语单词音标表.xlsx` | 120 个单词，含音标和中文释义 |
| 英文短句练习 | 英文文章 | `src/data/defaultEnglishSentences.ts` | 50 个日常英文短句，带中文翻译 |
| 中文段落练习 | 中文文章 | `src/data/defaultChineseArticles.ts` | 3 篇经典中文短文（200-500 字/篇） |
| 英文寓言三则 | 英文文章 | `src/data/defaultEnglishFables.ts` | 狐狸与葡萄、龟兔赛跑、蚂蚁与蚱蜢，带翻译 |

#### 4.3.3 加载策略

```
应用启动（App.tsx useEffect）
  ↓
检查 localStorage 中 "default_materials_loaded" 标记
  ↓
已标记 → 跳过
未标记 →
  ├── fetch public/default-materials/*.xlsx → SheetJS 解析 → 写入 IndexedDB
  ├── 导入 src/data/*.ts 中的内置文章 → 写入 IndexedDB
  └── 设置 localStorage "default_materials_loaded" = "v1"
```

- xlsx 文件放 `public/` 目录，通过 `fetch` 加载后由 SheetJS 解析
- 内置文章以 TypeScript 常量文件形式存在（`src/data/`），Tree-shaking 友好
- 标记存入 localStorage（轻量标记），防止重复导入
- 版本号策略：标记值为 `v1`，后续新增默认素材时可递增（`v2`），用户自动获得新素材
- 用户在素材管理中可删除默认素材，删除后不会自动恢复（除非手动清除标记或点击"恢复默认素材"）

#### 4.3.4 后续扩展

项目维护者新增默认素材的步骤：
1. 将 xlsx 文件放入 `public/default-materials/`
2. 在 `src/data/defaultMaterialsRegistry.ts` 中注册元信息（名称、类型、文件路径）
3. 递增标记版本号 `"default_materials_loaded" = "v2"`
4. 重新构建部署即可，已加载用户自动获得新素材（标记版本不匹配则触发增量导入）

### 4.4 GitHub Pages 部署

#### 4.4.1 部署架构

```
GitHub Repository
  ├── main 分支（源代码）
  │   └── GitHub Actions
  │       ├── npm ci
  │       ├── npm run build   → Vite 构建到 dist/
  │       └── 部署到 gh-pages 分支
  └── gh-pages 分支（静态文件）
      └── 由 GitHub Pages 提供服务
          └── https://<username>.github.io/<repo-name>/
```

#### 4.4.2 Vite 配置

```typescript
// vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import tailwindcss from '@tailwindcss/vite';

export default defineConfig({
  base: '/typing-master/',     // ⚠️ 必须与 GitHub 仓库名一致
  plugins: [react(), tailwindcss()],
  build: {
    outDir: 'dist',
  },
});
```

#### 4.4.3 GitHub Actions 工作流

```yaml
# .github/workflows/deploy.yml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
```

#### 4.4.4 数据持久化详解

用户最关心的一个问题：**"我导入的文件会丢失吗？需要重新导入吗？"**

| 场景 | 数据是否保留 | 原因 |
|------|-------------|------|
| 关闭标签页再打开 | ✅ 保留 | IndexedDB 持久化，同源同浏览器 |
| 刷新页面 | ✅ 保留 | 同上 |
| 同一浏览器第二天访问 | ✅ 保留 | 同上 |
| 浏览器更新 | ✅ 大概率保留 | IndexedDB 数据通常不受浏览器版本更新影响 |
| 换一个浏览器 | ❌ 不保留 | IndexedDB 按浏览器隔离 |
| 换一台电脑 | ❌ 不保留 | 存储在本机 |
| 清除浏览器缓存/数据 | ❌ 不保留 | 用户主动清除（建议先导出备份） |
| 隐私/无痕模式 | ❌ 不保留 | 会话结束后清除 |

**跨设备备份方案**：
- 设置页面提供「导出数据（JSON）」按钮 → 下载包含所有素材 + 练习记录的备份文件
- 提供「导入数据」按钮 → 在新设备上恢复完整数据
- 此项在 Phase 4 中实现

**存储上限**：IndexedDB 通常为浏览器可用磁盘空间的 50%-60%，素材量正常使用远达不到上限。

### 5.4 打字引擎核心逻辑

```typescript
// typingEngine 状态机
type EngineState = 'idle' | 'running' | 'paused' | 'finished';

interface KeyResult {
  type: 'correct' | 'incorrect' | 'backspace' | 'finished';
  nextChar: string | null;  // ★ 下一个待按键位字符
}

interface TypingEngine {
  state: EngineState;
  target: string;           // 目标文本
  input: string;            // 用户已输入
  cursor: number;           // 当前字符位置索引
  errors: Set<number>;      // 错误位置集合
  startTime: number | null;

  start(): void;
  handleKey(key: string): KeyResult;
  handleBackspace(): void;
  finish(): SessionResult;
}
```

**字符级别判定**：
- 每次按键时，比对 `input[cursor]` 与 `target[cursor]`
- 正确：cursor 前进，`KeyResult.nextChar = target[cursor+1]`
- 错误：cursor 前进，记录错误位置，`KeyResult.nextChar = target[cursor+1]`
- 退格：cursor 回退，清除该位置的错误标记，`KeyResult.nextChar = target[cursor]`
- **`nextChar` 直接驱动 VirtualKeyboard 的高亮目标**

## 9. 素材导入规范

### 9.1 xlsx 单词表规范

**最低要求**：至少包含"英文"列和"中文"列。

**推荐格式**：

| 序号 | 单词/短语 | 英式音标 | 美式音标 | 中文 |
|------|-----------|----------|----------|------|
| 1 | apple | /ˈæpl/ | /ˈæpəl/ | 苹果 |
| 2 | banana | /bəˈnɑːnə/ | /bəˈnænə/ | 香蕉 |

**解析规则**：
1. 自动跳过首行（如果识别为标题/表头）
2. 跳过空行和纯 None 行
3. 跳过 `Unit N` 等分组标记行（正则匹配）
4. 用户手动映射列 → 字段

### 9.2 文章 TXT 规范

**中文文章**：纯文本，UTF-8 编码，段落间用空行分隔。

**英文文章**（带翻译）：
```text
A fox one day spied a bunch of ripe grapes hanging from a vine.

---translation---
一天，一只狐狸发现了一串熟透的葡萄挂在藤蔓上。

The grapes seemed ready to burst with juice.

---translation---
葡萄看起来汁水充盈，快要胀破了。
```

**Markdown 文章**（带翻译）：
```markdown
## The Fox and the Grapes

A fox one day spied a bunch of ripe grapes hanging from a vine.

> 一天，一只狐狸发现了一串熟透的葡萄挂在藤蔓上。
```

### 9.3 支持编码

- UTF-8（推荐）
- UTF-8 BOM
- GBK / GB2312（自动检测并转换）

## 10. 风险与对策

| 风险 | 影响 | 概率 | 对策 |
|------|------|------|------|
| **虚拟键盘渲染性能** | 快速打字时键盘更新卡顿 | 中 | `React.memo` + 模块级常量 + CSS 动画非 JS 动画；keydown 驱动而非轮询 |
| **大文本性能问题** | 文章模式输入卡顿 | 中 | `contentEditable` 替代受控 input + 虚拟滚动仅渲染可视区域 |
| **IndexedDB 浏览器兼容性** | 部分旧浏览器无法存储 | 低 | 检测支持，不支持时降级为 localStorage |
| **xlsx 格式多变** | 解析失败或字段错位 | 中 | 导入向导让用户手动映射列，不做全自动猜测 |
| **中文输入法干扰** | 逐字符判定与组合态冲突 | 高 | compositionstart/end 事件处理；组合态期间虚拟键盘暂停高亮 |
| **SheetJS 体积较大** | 首屏加载慢 | 低 | 动态 `import()` 懒加载，仅在导入功能触发时加载 |
| **键盘布局差异** | 非 QWERTY 用户虚拟键盘不匹配 | 低 | 比对 `key` 值非 `keyCode`；虚拟键盘标注 "QWERTY 参考"，未来可扩展布局切换 |
| **GitHub Pages 部署失败** | 用户无法访问 | 低 | 本地 `npm run build && npm run preview` 先验证；Actions 日志可排查 |
| **默认素材 xlsx 加载失败** | 首次启动无内置素材 | 低 | fetch 失败时静默降级（依赖用户导入）；内置 TS 文章常量不依赖网络 |
