## Bug 分析

### Bug 1：退格率超过 100%

**现象**：统计页和首页的退格率数值可能超过 100%。

**根因**：`backspaceCount` 和 `totalKeystrokes` 在切换素材时没有重置。

- WordTypingPage 在 `startPlan` 中调用了 `typing.resetStats()`，能正确重置。
- **ArticleTypingPage 的 `handleSelect` 直接调用 `typing.init()`，从未调用 `typing.resetStats()`**。
- 用户在两个不同文章素材间切换时，上一个素材的退格数会被带到下一个素材的统计中。
- 单词模式↔文章模式之间切换也不会重置。

**涉及的聚合计算**：
- DashboardPage `today.avgBks`：`reduce(backspaceCount / totalKeystrokes * 100) / count`
- StatsPage `overview.avgAcc`：同上逻辑
- StatsPage 列表项：`Math.round(s.backspaceCount / s.totalKeystrokes * 100)`
- 单 session 内退格率理论上永不超过 100%（每次退格+1，total 也+1），但跨素材累积可能导致 session 中退格来自另一个素材的输入

**修复方案**：
在 `ArticleTypingPage.tsx` 的 `handleSelect` 函数中，`typing.init()` 之前加入 `typing.resetStats()`：

```typescript
// 约第 65 行，handleSelect 内：
typing.resetStats(); // ← 新增
typing.init(paras[0], id, mat.name, "sequential");
```

**涉及文件**：`src/features/article-mode/ArticleTypingPage.tsx`（1 行）

**验证方式**：在素材间切换后检查 StatsBar 显示的退格数是否归零。

### Bug 2：文章打字超出目标字符数后 Enter 能跳段

**现象**：目标 `aaaaa`，用户输入 `aaaaab`，按 Enter 也能进入下一段。

**根因有两个层面**：

1. **Enter 条件过宽**：`ArticleTypingPage.tsx` 第 ~108 行
   ```typescript
   if (st.cursor >= st.target.length && st.target.length > 0 && errorIndicesRef.current.size === 0) advance();
   ```
   使用 `>=` 而非 `===`，允许输入长度超过 target。

2. **Error 检测不完整**：`updateErrors()` 函数
   ```typescript
   for (let i = 0; i < Math.min(st.input.length, st.target.length); i++) {
     if (st.input[i] !== st.target[i]) inds.add(i);
   }
   ```
   `Math.min` 导致超出 target 的字符从不被检测为错误，`errorIndices.size` 永远为 0。

**修复方案**：

改 `updateErrors`：将超出部分的字符也标记为错误
```typescript
const updateErrors = () => {
    const st = getTypingState();
    const inds = new Set<number>();
    for (let i = 0; i < st.input.length; i++) {
      if (i >= st.target.length || st.input[i] !== st.target[i]) inds.add(i);
    }
    setErrorIndices(inds);
};
```

改 Enter 条件：用 `st.input.length >= st.target.length` 替代 `st.cursor >= st.target.length`（两者等效但更清晰），配合上面修复即可。

**涉及文件**：`src/features/article-mode/ArticleTypingPage.tsx`（2 处，约第 86 行和第 108 行）

**验证方式**：输入超出目标长度的字符，确认 Enter 无法跳段。

### 需求 2：段落用空格分隔 5 字符组

**目标**：当前每行一个段落（如 `aaaaa`），改为多组合并用空格隔开（如 `aaaaa sssss ddddd fffff ggggg`）。

**实施**：修改 `src/services/parser/textParser.ts` 中 `parseCharSeqContent` 函数：

```typescript
// 当前
const CHUNK_SIZE = 1;
for (let i = 0; i < lines.length; i += CHUNK_SIZE) {
    const chunk = lines.slice(i, i + CHUNK_SIZE);
    segments.push({ type: "paragraph", content: chunk.join("\n") });
}

// 改为
const CHUNK_SIZE = 5; // 5 组一个段落
for (let i = 0; i < lines.length; i += CHUNK_SIZE) {
    const chunk = lines.slice(i, i + CHUNK_SIZE);
    segments.push({ type: "paragraph", content: chunk.join(" ") }); // 空格连接
}
```

**涉及文件**：`src/services/parser/textParser.ts`（2 处改动）

**注意**：修改后所有使用 `parseCharSeqContent` 的素材（基础版和进阶版）都会按空格分隔。

### 需求 3：虚拟键盘 Shift 切换符号显示

**目标**：按 Shift 时，虚拟键盘上的符号键应显示上方字符（如 `1`→`!`，`[`→`{`），并且正确高亮。

**当前状态**：
- `VirtualKeyboard` 组件已接收 `shiftKey` 和 `capsLock` props
- 字母键按 Shift 能正确显示大写（`formatKey` 中 `upper ? key.toUpperCase() : key`）
- 但数字和符号键只做 `toUpperCase()`，对符号键无效果（`[` 的 `toUpperCase()` 仍是 `[`）
- `nextKey` 匹配使用 `nextKey?.toLowerCase()`，不处理 Shift 符号的高亮

**修复方案**：

1. 在 `keyboardLayout.ts` 中添加 Shift 符号映射表：
```typescript
export const SHIFT_MAP: Record<string, string> = {
  "`": "~", "1": "!", "2": "@", "3": "#", "4": "$", "5": "%",
  "6": "^", "7": "&", "8": "*", "9": "(", "0": ")",
  "-": "_", "=": "+",
  "[": "{", "]": "}", "\\": "|",
  ";": ":", "'": "\"",
  ",": "<", ".": ">", "/": "?",
};
```

2. 修改 `formatKey`：对符号键使用 SHIFT_MAP
```typescript
const formatKey = (key: string) => {
    if (key === "Space") return "";
    if (MOD_KEYS.has(key)) return key;
    if (upper && SHIFT_MAP[key]) return SHIFT_MAP[key]; // 新增
    return upper ? key.toUpperCase() : key;
};
```

3. 修改 `nextKey` 高亮匹配逻辑：当 Shift 按下时，同时匹配原始键和 Shift 映射键
```typescript
const next = nextKey?.toLowerCase() ?? null;
// 在 getKeyClass 中，isNext 的判断需要扩展：
const isNext = !disabled && !MOD_KEYS.has(key) && (
    next === lower ||  // 原始匹配
    (upper && SHIFT_MAP[key]?.toLowerCase() === next) ||  // Shift 符号匹配
    (!upper && SHIFT_MAP[key] && next === key.toLowerCase()) // 非 Shift 按下时匹配原始字符
);
```

**涉及文件**：
- `src/services/keyboardLayout.ts`（新增 SHIFT_MAP）
- `src/components/typing/VirtualKeyboard.tsx`（修改 formatKey 和 getKeyClass）
